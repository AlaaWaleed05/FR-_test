## Network (STEP 1) — the prior run's dead-end, resolved

Laptop + phone on the **iPhone hotspot** (`iPhone`, subnet 172.20.10.0/28). Laptop IPv4 **172.20.10.2**, phone 172.20.10.3. The recorded 192.168.0.5 from the earlier failed LAN was not used.

- **ICMP is a false negative here:** phone→laptop `ping` returned 100% loss, but a phone→laptop **TCP** fetch on 8080 succeeded (`FRU-NET-PROOF-OK`, then `http_401` from `/api/v1/auth/me`). The firewall hypothesis was disproven — no python/java/8080 rule exists yet the connection worked. Reachability was proven by HTTP, not ping.
- adb: flipped to TCP/IP (`adb tcpip 5555`) to survive the unstable cable, but **this device reverts adbd to USB mode on every cable unplug** (Android 9, no root — `tcpip` does not persist). Net effect: the cable had to stay connected for the run; logcat ran over USB while the app's own traffic ran over Wi-Fi (independent transports).

## STEP 4 — Error cases (account 0000000101)

### Cancel / F-1 — first-ever hardware execution ✅

PO cancelled via the **SDK's own back navigation** (back-arrow on the camera → SDK intro screen → back again → out).

- Logcat: `io.uqudo.sdk.scanner.view.ScannerActivity` + `io.uqudo.sdk.core.EnrollmentActivity` launched (camera live ~15 s), then **tore down cleanly** (EXITING → removeAppToken) at 17:35:00.
- Audit: `scan_token_issued` 15:34:43 → `scan_cancelled` **15:34:58.70** (matches the teardown to the second) → rejected screen showing **"تم احتساب محاولة"** (attempt counted). Resolved in **~2 s**.

| F-1 question | Hardware answer |
|---|---|
| Timeout arm or SDK cancel? | **SDK cancel** — the 180 s `UqudoScanNoResponse` arm was never entered |
| Attempt spent via `/cancel`? | **Yes** (`scan_cancelled`) |
| Rejected screen, not "no attempt counted"? | **Yes** ("تم احتساب محاولة") |
| Dead spinner / hang? | **None** |

**The failure F-1 defends against did not manifest.** The app's scanner ([plugin_uqudo_scanner.dart:71-107](../../mobile/lib/core/identityscan/plugin_uqudo_scanner.dart#L71-L107)) reads the SDK `SessionStatusCode` from the JSON envelope in `PlatformException.code`; combined with the fast resolve + `scan_cancelled`, this pins the path to **`USER_CANCEL`**, not the null-Intent `RESULT_CANCELED` shape BL-053 describes. The SDK's UI back-out reports the cancel promptly — the ~180 s dead-spinner premise of BL-054 was **not observed** for this gesture. F-1 remains a correct guard for the still-unobserved null-Intent path (which may be unreachable through normal SDK UI).

**Observability limitation:** the debug build emits **no `I/flutter` lines to logcat** on this EMUI ROM — the app catches the `PlatformException` in Dart and acts on it. So "USER_CANCEL" is identified by behaviour + code path + audit, **not** a verbatim logcat line. Filed as **BL-055**.

### Camera permission denied ✅

Camera permission revoked via `pm revoke` (which force-restarted the app — an adb artifact, not a user path; the app resumed correctly to the Stage 8 pre-scan screen). PO tapped Start → denied the OS prompt.

- Screen: distinct **"لا يمكن الوصول إلى الكاميرا … لم يتم احتساب أي محاولة"** (cannot access camera … no attempt counted), single Retry button — the `_Stage8View.cameraDenied` view.
- Audit: `scan_token_issued` 15:46:23 (token mints at point-of-use) but **no `scan_cancelled`** → **no attempt spent**. Matches `isCameraUnavailable` (`SESSION_INVALIDATED_CAMERA_PERMISSION_NOT_GRANTED`) skipping `/cancel`.

Note: a Uqudo token *is* consumed even when the customer denies/cancels before capture — correct by design (token issuance ≠ retry attempt, customer.md Stage 8), but it draws tenant token quota. Informational.

## What this run did NOT prove — stated, not faked

- **Registry not-found / unreachable screens — not device-producible in stub config.** The registry NID is `parsed.identityNumber()` from the scanned document, not a typed field, so the seeds `NID-TEST-NOT-FOUND` / `NID-TEST-UNREACHABLE` cannot be hit by a real passport, and forcing them would require writing the PO's real ID number into the stub config (declined — CLAUDE.md hard rule, not waivable by PO consent). The brief's assumption presumed a typed-NID path that does not exist on-device. These screens stay **backend-test-covered** (S3-14, S5-11); recorded as a correction, not a defect.
- **SDN_ID — unproven.** No Sudanese national ID card available (PO). The parser's national-ID branch stays `[UNVERIFIED]` (R-034 residual). The brief allows this.
- **SCAN_BLOCKED / 24 h block, REGISTRY_PENDING** — backend-covered, out of on-device scope, not synthesized.
