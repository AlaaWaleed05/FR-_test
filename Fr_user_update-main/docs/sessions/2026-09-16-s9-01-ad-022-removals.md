## Ruling 1 — manual completion deleted (`387896e`)

Thirteen files deleted (11 backend, 2 back office). The brief's list missed `ProfileNotManuallyCompletableException` (its only
two references were the files being deleted) and `SecurityConfiguration:134`'s `*/manual-complete`
matcher. The matcher removal is deliberate rather than the tidying the neighbouring comment
forbids — that note protects matchers claimed for endpoints *not built yet*; this guarded one that
is gone for good. One behavioural consequence is recorded rather than glossed: a signed-in viewer
POSTing that path now gets 404 rather than 403. No authorisation is lost; there is no route for
anyone.

**`app.profile_status_history.is_manual_completion` is kept, write-never and read-still.** The read
path is annotated at both ends (`types.ts`, and the timeline tag in `ProfileDetailPage.tsx`) so a
later grep does not remove the column's last consumer.

**V0071 corrects a false statement that was live in the database catalogue.** V0067's applied
`COMMENT ON COLUMN` says the column "is retained and still written so it can be restored without a
migration". Both halves are now false. V0067 is not edited (BL-144); `COMMENT ON COLUMN` overwrites
by replacement.

### Three tests re-pointed, not deleted

- **`actorIdIsTheUuidSoARenameDoesNotRewriteHistory`** proves AD-002e R1. Its Javadoc records that
  AD-013 already took its four-eyes vehicle once; AD-022 took its second. Re-pointed a third time
  at approve, which still writes both a history row and an audit event carrying `actor_id`. The
  Javadoc now explains why the subject outlives its vehicles, so the next session re-points rather
  than deletes. **No revert-restore needed**: both assertions are direct wrong-value assertions —
  if `operatorId` were the username, `assertEquals(operatorAId.toString(), historyActorId)` fails
  before the two `assertNotEquals` matter.
- **`ProfileExportIntegrationTest`**'s subject is the export column's meaning, not manual
  completion. Since nothing can now produce a `manual` profile, its driver became a raw-SQL seed
  matching how a legacy row still reads.
- Two back-office tests moved from the deleted button to the print action, the remaining third
  `mayAct` gate.

### A regression guard that would have vanished silently

`ManualCompletionIntegrationTest` held the **only** test for S8-07's "an already-issued `FRU-`
number is never rewritten" — while `SubmissionRepository`'s javadoc, edited in this same commit,
still asserts that property. Deleting the file would have left a documented guarantee with nothing
behind it. Re-homed into `SubmissionIntegrationTest` via resubmission; submission is now the sole
mint site. Found by `@agent-reviewer` on this session's own diff.

## Ruling 2 — one printed form (`a102ff2`)

`PrintedFormVariant` deleted; the choice is gone from `PrintRequest` (and with it the controller's
400 arm), the service, the assembler, the FO writer, the repository and the print modal. The
attachments option is untouched, including its asked-every-time fresh-mount reset.

**The navy attribution banner is removed rather than shown on every print — and the first version
of that rationale was WRONG.** I wrote that the banner promised something that never rendered,
because `PrintedField.enteredBy` "has always been null on both variants". `@agent-reviewer` refuted
it with the deleted assertions: `PrintedFormAssemblerTest` asserted `attributed.enteredBy()` equals
`"op-manual-1"`, and `PrintedFormRendererTest` asserted the rendered text contains
«يدوي — مشغّل تجريبي». **The banner rendered and the name appeared.** The source of the error was
`PrintedField`'s own javadoc, which said "null today on both" — a stale comment I trusted instead
of reading the assembler. The removal still stands, for the true reasons: the name was the
PROFILE-level manual completer, not a per-field editor; it rendered only on the ATTRIBUTED variant
while the menu defaulted to UNATTRIBUTED; and ruling 1 leaves no profile able to be `manual`, so
the banner would announce an attribution that can no longer occur.

`manualCompletionOperator` and its field went with it — once the name is never passed they walked
the entire status history on every assemble to compute a value nothing read. `PrintedField.enteredBy`
is retained for BL-135 and S9-03, and now says so.

**V0072 purges the old kind.** The `UPDATE` re-labelling `printed_form_attributed` rows comes
FIRST, and that ordering is the whole correctness of the migration: `ADD CONSTRAINT` validates
existing rows by default, so re-adding the narrowed CHECK while one attributed row survived would
fail outright against staging, which has run V0070. Rows are re-labelled, not deleted — they are
filed bank documents and stay re-downloadable. The migration also re-issues the
`COMMENT ON CONSTRAINT` that `DROP CONSTRAINT` silently discards; **nothing asserts a constraint
comment exists, so no gate would have caught its loss.**

The audit payload DROPS `variant` rather than pinning it to a constant. Events already written keep
theirs, so which form a historical print was stays recoverable from the append-only trail.

Two tests added rather than only removed: the schema test proves the narrowed CHECK **actually
refuses** the withdrawn kind (savepoint-guarded; it cannot pass against an unmigrated database),
and a stale-client test pins that a browser still sending `variant` is ignored, not refused — the
back office deploys separately, so refusing it would break printing for as long as that cache lives.

## Rulings 3 and 4 — display only (`42b492f`)

**The trap the audit caught.** The liveness success line AD-022 explicitly preserves is itself
derived from `detail.faceResult`; there is no independent liveness signal on the wire. A naive
"remove every `faceResult` reference" deletes «اكتمل التحقق الحي بنجاح.» — the one line the ruling
protects. The read is kept as a completed-ness predicate with a comment loud enough that the next
reader cannot make that mistake. The capture path is untouched, and
`OperatorProfileViewIntegrationTest:78` still asserts `faceResult.passed` on the wire against the
real database.

Channels filter on the wire's own `state === 'verified'`, not on `verifiedAt` — separate columns
(V0007), so filtering the timestamp would infer state from a proxy. The fixture carries one channel
of each state, so the test fails in both directions.

Two consequences the brief did not name: the per-channel state Tag could now only ever read
«موثّق», so it is dropped — a label with one reachable value tells an operator nothing and invites
them to hunt for the others — and `CHANNEL_STATE_COLORS` died with it.

**A defect my own test could not catch.** The no-verified-channels empty state first rendered the
Alert *in addition to* the grid: antd draws the bordered `.ant-descriptions-view` whatever the row
count, so the stray empty box the comment claimed to avoid was still drawn. Now a ternary, with the
test asserting the Alert's previous sibling is the section Divider. That assertion took three
attempts — the first matched other grids on the page, the second anchored to whichever alert came
first in the DOM — **and all three would have passed.** Only the third fails against the broken
version.

## What failed, and what it cost

- **`spotless:apply` must be the LAST backend edit.** Applied it, then made two more comment
  corrections; the check failed on exactly those two files.
- **A piped `| tail` swallows Maven's exit code.** The background-task notification reported
  "exit code 0" on a build that had **failed on Spotless**, and again later on a run with two real
  test failures. Every gate since is written to a log with `MAVEN_EXIT=$?` appended, and the exit
  code is read from the log rather than from the notification. A session trusting those
  notifications would commit a red gate believing it green.
- **A bulk regex edit silently halved an assertion.** Collapsing two variant call sites produced
  `assertThat(...).isEqualTo("op-print-1")` twice in `theFormNamesTheOperatorWhoPrinted` — the
  second line proved nothing. Caught at review.
- **Scripted plan-file edits go in a script FILE, never a heredoc.** The first attempt died on
  quoting; the four reconciliation passes are `.py` files written with the Write tool.
